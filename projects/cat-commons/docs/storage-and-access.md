# CAT Commons storage and access

## Authoritative system

The canonical resource library lives in a Foundation-controlled Google Drive folder. GitHub is authoritative only for governance, provenance, folder identity, and verification records. Large binaries and private exports never enter Git.

The exact owner account is recorded in the private Joka Source operations inventory after the migration is accepted. Public documentation records the role, not a personal recovery address.

## Folder boundary

The public library and any private migration archive are separate roots.

### Public library

- Viewer access may be enabled for anyone with the link only after a rights review.
- Editor access is limited to named cell stewards.
- Contains author-owned work, official links, and material with verified redistribution rights.
- Contains no learner records or correspondence.

### Private migration archive

- Temporary destination for source material whose rights or relevance are unresolved.
- Restricted to the owner and designated rights reviewer.
- Never linked from the public library or JSF repository.
- Each item is either cleared, deleted, returned to its owner, or retained under a recorded lawful basis.

Commercial coaching recordings and torrent-derived material are not a JSF public asset. Moving an existing private archive between accounts does not grant redistribution rights.

## Migration safety

1. Record source folder IDs, current owner, collaborators, and general-access mode.
2. Grant the destination owner access without removing existing collaborators.
3. Transfer or copy cloud-to-cloud; do not bypass file safety warnings.
4. Compare destination and source item counts by top-level section.
5. Open the guide and one representative item from every public section.
6. Verify the destination owner, public access, and editor list.
7. Keep the source intact until the destination accepts ownership and recovery evidence exists.
8. Only then remove source duplicates, followed by Drive storage readback.

## Access policy

| Role | Access |
|------|--------|
| Aspirant | Viewer on the rights-cleared public library |
| Cohort steward | Editor on the public library; cannot expose the private archive |
| Resource steward | Editor plus provenance and rights-review responsibility |
| Foundation owner | Owner, recovery, and export responsibility |

No learner needs editor access to consume the library. Link possession is not authority to edit, upload, or expose restricted material.

## Retention

- Review guide links, exam-year claims, owners, and stewards before every cohort.
- Review public artifacts annually and remove stale or superseded copies.
- Keep only the current guide plus explicitly archived prior editions.
- Resolve private migration items within 90 days of discovery.
- Do not retain learner-level activity data in this project.

## Protection and recovery

- Require two-step verification on the owner account and recovery methods outside any graduating student's institutional email.
- Maintain at least two named stewards.
- Export the public library annually to an encrypted offline location outside Git.
- Record a value-blind hash manifest and item counts.
- Perform a sample restore before each cohort and record only non-sensitive evidence in JSF.
- If the owner account is lost, the recovery steward restores the latest rights-cleared export to a new Foundation-controlled folder and updates the canonical link.

## Publication verification

The library is cohort-ready only when a signed-out browser can:

1. open the canonical folder;
2. see *HowToACE - CAT 1.1* first;
3. navigate the seven public sections;
4. open every official link; and
5. find a current help and feedback route.

Folder health or an authenticated owner view is not sufficient proof of the public aspirant journey.
